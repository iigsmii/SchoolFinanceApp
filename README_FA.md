# SchoolFinanceApp 2.15.0 | بازطراحی و اصلاحات

این ZIP شامل سورس کامل برنامه اندروید، سرور Apps Script، فایل‌های Gradle، منابع،
نمونه‌داده‌های پروژه اصلی، گردش ساخت GitHub و تست‌هاست؛ صرفاً یک پچ نیست.
اصلاحات از قبل روی سورس اعمال شده‌اند. اسکریپت پچ قدیمی را دوباره اجرا نکنید.
راهنماهای README قدیمی فقط سابقه نسخه‌های قبل هستند؛ این فایل مرجع این بسته است.

**وضعیت تحویل: کاندید آزمایش، نه نسخه تأییدشده برای حسابداری زنده.**
۲۸ تست سرور با شبیه‌ساز محلی، ۵۸۴۳ آزمون رفت‌وبرگشت تاریخ، بررسی نحو Java و XML
انجام شده‌اند. APK در این محیط ساخته یا روی گوشی آزمایش نشده و Google Apps Script
روی حساب واقعی اجرا/منتشر نشده است. نتیجه واقعی تست‌ها در TEST_RESULTS.txt است.

## اصلاحات سازگاری در شاخه fix/apps-script-compatibility

- doGet اکنون پارامترهای query از جمله token/authToken را به handler می‌دهد؛ خود handlerها همچنان احراز هویت و محدودیت نقش را اجرا می‌کنند.
- پاسخ sync فقط فهرست مدیران را برای نقش‌های senior/admin برمی‌گرداند؛ نقش‌های دیگر فهرست خالی می‌گیرند.
- نسخه پاسخ سلامت و app_version با 2.15.0 هم‌راستا شده است.
- کلاینت برای عملیات مالی محافظت‌شده request_id می‌فرستد و در retry خودکار همان بدنه را تکرار می‌کند؛ اگر کاربر پس از دریافت خطا عملیات را دستی دوباره ثبت کند، این نسخه شناسه قبلی را به‌صورت پایدار میان دو بار کلیک ذخیره نمی‌کند.
- این تغییرات در شاخه جداگانه هستند و هنوز روی Google Apps Script واقعی یا APK نصب‌شده آزمایش زنده نشده‌اند. پیش از استفاده مالی، چک‌لیست پذیرش پایین را در کپی آزمایشی اجرا کنید.

## ظاهر جدید

رابط همچنان Native Java است؛ هیچ WebView یا اپ نمایشی جایگزین منطق اصلی نشده است.
رنگ آلوئی و زمینه روشن، سربرگ ساده، کارت خوشامد، خلاصه واقعی دانش‌آموزان و بدهی،
آیکون‌های خطی یکدست، دکمه‌های لمسی با اندازه مناسب، حالت فوکوس فیلدها و فرم
دانش‌آموز اسکرول‌شونده اضافه شده‌اند. کارت‌های داشبورد دیگر به شکلک فونت گوشی وابسته نیستند.
منوها و مسیرهای اصلی قبلی حفظ شده‌اند؛ همه فرم‌های قدیمی از پایه بازنویسی نشده‌اند.
فونت از خانواده سیستمی sans-serif است؛ فونت تجاری بدون مجوز به بسته اضافه نشده است.

## قبل از جایگزینی

1. از پروژه، Google Sheet و پوشه پیوست‌های Drive پشتیبان مستقل بگیرید.
2. ابتدا یک کپی Sheet و یک پروژه/deployment آزمایشی Apps Script بسازید.
3. در سرور مقدار CFG.SPREADSHEET_ID و در ApiClient.java مقدار BASE را برای محیط
   آزمایشی تنظیم کنید. شناسه و نشانی فعلی پروژه اصلی برای سازگاری حفظ شده‌اند.
4. سرور و APK این بسته را هماهنگ منتشر کنید. نسخه جدید کلاینت برای ثبت‌های مالی
   شناسه request_id می‌فرستد و در تلاش مجدد خودکار همان شناسه را نگه می‌دارد؛ نسخه‌های
   قدیمی ممکن است شناسه پایدار نفرستند و تکرار دستی ثبت در آن‌ها تضمیناً خنثی نمی‌شود.
5. در زمان مهاجرت، ثبت مالی نسخه قبلی را متوقف کنید؛ نشست‌ها پس از انتشار باید
   دوباره ساخته شوند. مهاجرت را هم‌زمان با ثبت زنده انجام ندهید.

## آماده‌سازی Google Apps Script

1. کل SchoolFinanceApp_GoogleAppsScript_FINAL.gs را جایگزین کد پروژه آزمایشی کنید.
   فایل check.js سرور نیست؛ در این بسته ابزار تکراری قدیمی حذف شده است.
2. زمان پروژه Apps Script را Asia/Tehran تنظیم کنید.
3. برای دیتابیس موجود، setup() را یک‌بار دستی اجرا کنید. این تابع Sheet جدید Requests
   و ستون image_url چک را اضافه می‌کند و داده مالی موجود را پاک نمی‌کند.
   setup همچنین نسخه تنظیمات را به 2.15.0 می‌برد؛ ابتدا فقط روی کپی آزمایشی اجرا شود.
4. برای نصب تازه بدون حساب admin، در Project Settings > Script Properties مقدار
   INITIAL_ADMIN_PASSWORD را با رمز تصادفی حداقل ۱۲ نویسه بسازید و setup() را اجرا کنید.
   پس از ساخت حساب، این property حذف می‌شود. حساب‌های فعلی مدیران باقی می‌مانند؛
   مدیران نمونه و هش رمزهای عمومی دیگر در سورس جاسازی نشده‌اند.
5. برای تعویض رمز admin موجود، ROTATED_ADMIN_PASSWORD را با رمز جدید حداقل
   ۱۲ نویسه تنظیم و تابع rotateAdminPassword() را فقط دستی اجرا کنید.
   این تابع رمز را عوض و property را حذف می‌کند؛ نشست‌های قبلی نامعتبر می‌شوند.
6. رمز تمام حساب‌هایی را که هش آن‌ها قبلاً عمومی شده بود عوض کنید. حذف هش از سورس،
   رمزهای موجود Sheet یا تاریخچه GitHub را خودکار پاک نمی‌کند.
7. یک نسخه جدید Web App منتشر کنید؛ ذخیره‌کردن فایل به‌تنهایی انتشار نیست.
   Web App با هویت مالک اجرا می‌شود و احراز هویت در handlerهای برنامه انجام می‌گیرد.

## ساخت اندروید

ساخت پیشنهادی: workflow با نام Android Release APK (signed).
همان Secretها و همان کلید امضای نسخه نصب‌شده قبلی را استفاده کنید؛ کلید جدید باعث
ردشدن به‌روزرسانی درجا می‌شود. کلید یا رمز امضا داخل ZIP قرار نگرفته است.
گردش Source regression checks فقط تست است و APK بدون امضا منتشر نمی‌کند.

این پروژه مانند نسخه اصلی Gradle Wrapper باینری در بسته ندارد. برای ساخت محلی،
Android SDK 33، Build Tools 33.0.2، Gradle 7.0.2 و JDK 11 نیاز است:

```sh
python3 tools/verify_project.py
gradle --no-daemon clean assembleDebug
```

نسخه پیش‌فرض 2.15.0 و versionCode پیش‌فرض 5 است. اگر نسخه نصب‌شده کد بالاتری دارد:

```sh
gradle assembleRelease -PversionCodeOverride=101 -PversionNameOverride=2.15.1
```

شماره نسخه/کد نسخه، مقدار android_version در Settings و APK منتشرشده باید یکی باشند.
فیلد android_apk_url را فقط پس از ساخت و امضای فایل واقعی تنظیم کنید.
فایل APK آماده در این ZIP نیست. پذیرش Google Play با targetSdk فعلی ارزیابی نشده است.

## تغییرات مالی و امنیتی مهم

- تبدیل تاریخ از Activity جدا و روزهای مرزی اصلاح شده‌اند. تاریخ نامعتبر دیگر امروز نمی‌شود.
- نوشتن‌های API با ScriptLock هماهنگ شده‌اند؛ خواندن POST بدون قفل نوشتن انجام می‌شود.
- ثبت شهریه/هزینه/بدهی گروهی/عملیات عمومی و بررسی چک از شناسه پایدار درخواست استفاده می‌کنند.
- ویرایش شهریه به تراکنش متناظر منتقل و payment_source حفظ می‌شود.
- حذف مالی از نوع void است؛ سابقه باقی می‌ماند و از جمع‌ها حذف می‌شود. اسناد تأیید/تطبیق‌شده
  مستقیم ویرایش یا حذف نمی‌شوند. ابزار UI برای سند اصلاحی/برگشت عمومی در این بسته افزوده نشده است.
- پرداخت چک برگشتی از شهریه و تراکنش فعال کنار می‌رود تا بدهی دانش‌آموز دوباره محاسبه شود.
- تطبیق خودکار بانک فقط با مرجع یکتا و مبلغ/مدرسه یکسان انجام می‌شود؛ مبلغ تنها کافی نیست.
  تطبیق دستی، تأیید مدیر را به‌صورت خودکار فعال نمی‌کند.
- تصویر چک در Cheques ذخیره می‌شود، نه روی شهریه‌ای با شناسه عددی مشابه.
- پیوست‌های جدید خصوصی‌اند؛ اپ تصویر را از endpoint احراز هویت‌شده دریافت می‌کند.
  عمومی‌بودن فایل‌های قبلی خودکار تغییر نکرده است. پیش‌نمایش قدیمی با source_id خراب ممکن است
  نیاز به اصلاح metadata داشته باشد؛ دسترسی عمداً در حالت ابهام رد می‌شود.
- توکن در بدنه POST است، حجم فایل حداکثر ۵ مگابایت و پاسخ شبکه حداکثر ۸ مگابایت است.
- نشست حساب غیرفعال/رمز عوض‌شده رد می‌شود، تلاش ورود محدود و backup اپ غیرفعال شده است.
- APK آپدیت باید HTTPS، متعلق به همین package، جدیدتر و دارای همان امضای نصب فعلی باشد.
- ورود XLSX بانک در اپ نام فایل صحیح و انتخاب مدرسه ارشد دارد. دوربین از فضای خصوصی
  و FileProvider استفاده می‌کند؛ PDF در Android قدیمی در فضای خصوصی ذخیره و قابل اشتراک‌گذاری است.

## رسیدگی به وضعیت REVIEW در Requests

Requests دفتر جلوگیری از اجرای دوباره عملیات است. DONE پاسخ قبلی را برمی‌گرداند.
PENDING یا REVIEW به معنی «نتیجه نامطمئن» است و عملیات خودکار تکرار نمی‌شود.
مدیر ارشد باید با request_id، گزارش فعالیت و رکوردهای Tuition/Expenses/Transactions/Cheques
نتیجه واقعی را بررسی کند. بدون تطبیق داده‌ها، این ردیف را پاک نکنید یا کلید جدید نسازید.
Apps Script و Sheets تراکنش دیتابیس واقعی نیستند؛ جبران خطای دو نوشتن best-effort است.
قطع سخت اجرا یا تمام‌شدن سهمیه می‌تواند همچنان نیاز به بررسی دستی داشته باشد.
تست رقابت هم‌زمان واقعی و خرابی سهمیه Google در این محیط انجام نشده است.

## چک‌لیست پذیرش روی محیط آزمایشی

1. ورود مدیر و ارشد، تغییر رمز، خروج و غیرفعال‌کردن حساب دارای نشست فعال.
2. تاریخ‌های ۱۴۰۵/۰۱/۱۲ و ۱۴۰۵/۰۷/۰۹، اسفند کبیسه و رد روز ۳۱ ماه هفتم.
3. ثبت شهریه نقدی و بانکی، ویرایش مبلغ و تطبیق مقدار در هر دو Sheet.
4. قطع اینترنت پس از ارسال، ارسال مجدد همان اطلاعات و کنترل نبود ثبت مالی دوم.
5. بدهی گروهی، شکست شبیه‌سازی‌شده ثبت و رفتار REVIEW.
6. ثبت چک با عکس، تأیید دریافت و دروجه، رد چک، تطبیق پاس‌شده و برگشتی.
7. ورود فایل XLSX بانک واقعی، مرجع تکراری، دو مبلغ مساوی و عدم تطبیق حدسی.
8. پیوست خصوصی برای مدرسه صحیح و رد دریافت از مدرسه دیگر؛ فایل بیش از ۵ مگابایت.
9. حذف ثبت تأییدنشده و کنترل جمع بدهی؛ رد ویرایش/حذف سند تأییدشده.
10. خروجی پارسیان، PDF، دوربین و گالری روی Android 6، 10 و 13+؛ اندازه فونت بزرگ.
11. نصب APK امضاشده با کلید قبلی، رد APK با امضای دیگر و versionCode کمتر.

## موارد باقی‌مانده و محدودیت‌های صریح

این بازنویسی کامل معماری یا حسابداری دوبل نیست. چک‌های عمومی طرف‌حساب در
finance_transaction هنوز مدل مستقل دانش‌آموزی Cheques نیستند. ورود CSV بانک که
قبلاً موفقیت صفر می‌داد، اکنون با پیام روشن رد می‌شود؛ ورودی پشتیبانی‌شده XLSX است.
اعتبارسنجی رسمی صیاد و checksum کد ملی اضافه نشده است. قالب ده‌رقمی ورودی مستقیم
کنترل می‌شود؛ بازیابی صفرهای اول در import برای سازگاری حفظ شده است.
هش SHA-256 رمزهای موجود برای سازگاری هنوز باقی است و جایگزین KDF مقاوم یا سرویس
احراز هویت حرفه‌ای نیست. داده تاریخی اشتباه، ثبت‌های تکراری قدیمی، چک‌های قبلاً برگشت‌خورده
و پیوست‌های قدیمی به‌صورت خودکار تعمیر نمی‌شوند.
ذخیره موقت تمام فرم‌ها هنگام مرگ پردازش و بازطراحی معماری تک-Activity انجام نشده است.
نباید این بسته را بدون ساخت APK، تست دستگاه و تست staging مستقیم روی حسابداری واقعی جایگزین کرد.

دو ابزار قدیمی apply_schoolfinance_fixes.py و check.js عمداً در ZIP نهایی قرار ندارند:
اولی برای متن نسخه قبلی بود و دومی نسخه تکراری/قدیمی سرور همراه اطلاعات اولیه حساب‌ها.
هیچ فایل runtime اندروید، فایل سرور فعال یا نمونه‌داده برنامه به این دلیل حذف نشده است.
جایگزین بررسی غیرمخرب، tools/verify_project.py است.
